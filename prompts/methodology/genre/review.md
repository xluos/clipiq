# 测评 / 产品类方法论

适用：数码评测、产品开箱、对比测评、好物推荐。结构强、可跳读、要有证据。

---

## 三幕骨架

```
问题（用户场景 / 痛点）→ 方案（产品介绍 / 演示）→ 证据（数据 / 对比 / 验证）
```

短视频 60s 内压缩：问题 5s + 方案 15s + 证据 10s + 推荐 5s。
中长视频按章节铺开：外观 / 性能 / 续航 / 体验 / 价格 / 总结。

---

## 规则

### R-REVIEW-001 痛点开场
- category: hook
- when: 0-5s
- hit: 用具体场景 / 痛点 / 反差陈述开场（"用了 X 之后再也回不去了"）
- violation: 开场是品牌方话术、规格表罗列、"今天给大家测评 X"
- fix: 把测评结论 / 最有反差的体验提到开头

### R-REVIEW-002 章节分明（中长视频）
- category: structure
- when: 整片
- hit: 测评维度（外观 / 性能 / 续航 / 体验 / 价格 / 总结）有清晰章节卡
- violation: 测评维度混杂，观众分不清在讲哪个维度
- fix: 加章节卡 / 字幕标题，每维度单独段落

### R-REVIEW-003 证据闭环
- category: structure
- when: 每个测评维度
- hit: 每个结论都有具体证据支撑（数据 / 截图 / 对比镜头 / 实测画面）
- violation: 结论多为主观陈述，无证据画面
- miss: 关键论点缺证据
- fix: 补上实测画面 / 数据图

### R-REVIEW-004 节奏：1.5× 语速
- category: pacing
- when: 旁白段
- hit: 旁白语速明显快于日常对话（1.2-1.5×），信息密度高
- violation: 语速松散、有大量停顿和语气词
- fix: 加快语速或剪掉停顿

### R-REVIEW-005 演示镜头近景
- category: density
- when: 产品演示段
- hit: 关键功能演示用近景 / 特写 / 屏幕录制，细节清楚
- violation: 全程中景，看不清细节
- fix: 补近景 / 特写镜头

### R-REVIEW-006 横向对比
- category: structure
- when: 整片
- hit: 至少有一次与竞品 / 旧款 / 替代方案的对比
- violation: 孤立讲一个产品，无参照系
- miss: 完全没有对比维度
- fix: 加入对比段，哪怕只是参数表

### R-REVIEW-007 结论明确
- category: completion
- when: 最后 30s（中长）或最后 5s（短）
- hit: 明确给出"适合谁 / 不适合谁 / 是否推荐"
- violation: 模棱两可结尾，看完不知道结论
- fix: 加一句明确的推荐 / 不推荐结论

### R-REVIEW-008 节奏切换点（10min 视频在 5-6 分钟位）
- category: engagement
- when: 中段
- hit: 在维度切换处有节奏缓冲（短故事 / 幽默插入 / 用户场景模拟）
- violation: 全程数据 / 评测密度无喘息
- fix: 插入一段使用场景情景再现 / 用户故事
