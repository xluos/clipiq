分析管线全景 v2

金字塔管线 — 从一段视频到结构化拉片报告的完整流程

STATUS · Current DATE · 2026-05-26 PIPELINE · v2 Pyramid
TL;DR
管线共 8 个阶段。前 4 步在本地完成素材准备（零 API 成本），后 4 步调用云端模型产出分析结果（按 token 计费）。核心设计原则：抽帧尽量多（便宜），预筛选按时长动态预算（覆盖每一秒），叙事结构用大模型（准确），主分析按 context 自动分段（不丢信息）。

00管线总览

八个阶段分两个区：素材准备区全部在本地运行（ffmpeg + 小模型），智能分析区调用云端大模型。每一层向上传递更浓缩的信息，这就是「金字塔」的含义。

01检测镜头切换

做什么用 ffmpeg 场景检测滤镜扫描视频，标记画面突变位置
输入原始视频文件 + 场景阈值（密集档 0.18 / 标准档 0.3 / 稀疏档 0.45）
输出时间戳数组——每个镜头的起始时刻
代价FREE ~2 秒（纯本地 ffmpeg）

这是管线的第一步，也是后续所有阶段的基础。镜头数量直接影响抽帧数量、预筛选预算、镜头合并工作量。阈值越低越敏感——快剪混剪可能切出 100+ 个镜头，慢节奏纪录片只有十几个。

02抽取关键帧

做什么从视频里按镜头结构抽出静态画面，作为后续分析的视觉素材
输入镜头时间戳 + 目标帧数
输出一组 JPEG 文件，标注所属镜头和精确秒数
代价FREE ~50ms/帧（ffmpeg seek）

抽帧策略

  • 每个镜头至少 1 帧（中点），不丢弃任何镜头
  • 每秒至少 1 帧——5 分钟视频至少抽 300 帧
  • 长镜头按时长比例多分（贪心策略：总是给「时长/已分帧数」最大的镜头加一帧）
  • 抽完做一轮 dHash 去重，画面几乎一样的帧自动合并
设计原则
抽帧是整条管线中最便宜的操作（300 帧 ≈ 15 秒），所以宁多勿少。多抽出来的帧有 dHash 去重和预筛选两道关卡，不会给后面造成负担。

03预筛选

做什么用本地小模型（0.8B）逐帧打标，标注场景类型、主体、信息量评分、视觉签名
输入候选帧的缩略图（320px）
输出每帧的结构化标签 + 精选后的帧子集
代价LOCAL GPU ~1.1 秒/帧，预算按视频时长动态计算

动态预算

预筛选时间预算不再是固定值，而是根据视频时长自动伸缩，保证每秒至少有 1 帧被预处理。密度档只影响倍率：

密度档倍率5 分钟视频预算可标注帧数
稀疏×0.5~165 秒~150 帧
标准×1.0~330 秒~300 帧
密集×1.5~495 秒~450 帧

均匀覆盖策略

如果候选帧数超过预算：

  • 预算够覆盖所有镜头 → 每个镜头取 1 帧标注，剩余预算给长镜头的额外帧
  • 预算不够覆盖所有镜头 → 按均匀间隔采样，保证标注的帧在时间轴上分布均匀

三轮精选

标注完成后：① 删除空镜和极低信息帧 → ② 视觉签名去重（同一个场景不重复）→ ③ 按 salience 评分取 top N 送给主分析。

04语音转写

做什么提取音轨，用 Whisper 识别带时间戳的逐句字幕
输入视频音轨（WAV）
输出字幕分段列表 [{start, end, text}]
代价LOCAL 或 CLOUD，本地约为视频时长 × 0.3

字幕对后续分析质量影响极大——告诉模型「画面里的人在说什么」。无音轨或纯音乐的视频跳过此步。

分界线
到此为止所有素材已就绪：镜头边界、关键帧（含标签）、字幕。接下来进入 LLM 驱动的分析阶段。

05镜头合并

做什么把每个镜头的帧标签 + 字幕打包给中等文本模型，产出镜头级语义描述
输入镜头时间区间、帧标签（caption / signature / salience）、对应字幕
输出每个镜头的 shotDescription + 代表帧索引
代价CLOUD 中等文本模型，每 3 个镜头一批并发，100 个镜头 ≈ 3-5 万 token

这是金字塔的中间层：把底层碎片（帧标签 + 字幕片段）压缩成镜头级语义描述，让后续的大模型不必逐帧看图。

06全局摘要与叙事结构

做什么综合所有镜头描述 + 字幕全文，推断视频类型、生成全局摘要、提取叙事结构线索
输入全部镜头描述、字幕全文、镜头统计
输出视频类型、全局摘要（200-400 字）、叙事结构（开场 / 高潮 / 结尾）
代价CLOUD 视觉大模型（优先），fallback 到中等文本模型。单次调用 ~1 万 token
本次升级
叙事结构线索（hook / climax / ending）从中等文本模型升级为视觉大模型。大模型对叙事弧线的判断更准确，直接影响主分析对每个片段在全局中定位的质量。

07主分析

做什么把关键帧图片 + 字幕 + 镜头描述 + 全局摘要送给视觉大模型，产出结构化节点时间轴
输入精选帧（JPEG base64）、字幕分段、镜头描述、全局摘要、方法论规则集
输出节点数组——每个节点含时间区间、标题、描述、情感、剪辑手法、镜头运动等
代价CLOUD 视觉大模型（主力消耗），图片 ~800 tok/帧

自动分段

管线根据模型 context size 自动决定处理方式：

SINGLE PASS
单次模式
所有内容能装进一次请求 → 一次出完整结果（节点 + 报告）。适合短视频或大 context 模型。
CHUNKED
分段模式
内容超出 context → 按镜头边界切段，每段独立产出节点，最后拼接。单个 shot 超大时自动降级裁帧。

每段帧数上限

不再硬编码 12 帧。根据模型 context 动态计算，用 70% 的 token budget 留给图片：

模型 Context每段预算每段帧上限
8k（本地小模型）~5k tok~12 帧（兜底值）
32k~22k tok~19 帧
128k（GPT-4o / Claude）~88k tok~77 帧
200k+~140k tok~120 帧

08方法论审计

做什么拿到完整节点列表，按方法论规则集逐条审计，生成全局剪辑报告
输入全部节点、全局摘要、字幕、规则集
输出每节点的方法论标签（命中 / 违反）+ 全局报告（节奏 / 结构 / 改进建议）
代价CLOUD 文本模型，单次 ~1-2 万 token

10设计原则

CHEAP FIRST
便宜的多做
抽帧（50ms/帧）和 dHash 去重几乎免费，所以宁可多抽再筛，不在便宜层丢信息。每秒至少 1 帧，每个镜头至少 1 帧。
BUDGET SCALES
预算跟内容走
预筛选预算按视频时长伸缩，主分析帧数按模型 context 动态算。不用固定数字卡住高密度视频或浪费大 context 模型的能力。
PYRAMID
向上压缩
每一层只传精华给上层。帧标签 → 镜头描述 → 全局摘要 → 节点。大模型只看最浓缩的信息，token 不浪费在碎片上。

备注

  • 耗时基于 Apple Silicon M 系列 + GPT-4o 云端典型场景，实际因模型和网络波动。
  • 预筛选为可选阶段（需要本地 GPU + 已下载模型），跳过时退化为 dHash 去重 + 时长公式选帧。
  • 缓存层覆盖所有 LLM 阶段，重新分析同一视频时未变化的阶段直接复用。
