分析管线全景

从一段视频到结构化拉片报告，每一步做了什么、花了多少钱

STATUS · Current DATE · 2026-05-25 PIPELINE · v2 (Pyramid)
TL;DR
管线共 8 个阶段，前 4 步在本地用 ffmpeg + 小模型完成（几乎零成本），后 4 步调用云端大模型产出节点和报告（按 token 计费）。一段 5 分钟视频标准档分析约消耗 30-90 秒、2-8 万 token。瓶颈不在帧数，在模型上下文容量。

00管线总览

视频从进入管线到产出报告，依次经过八个阶段。前半段是「素材准备」——把视频拆解为结构化的帧、镜头、字幕；后半段是「智能分析」——用大模型理解内容并输出节点时间轴和方法论审计。

01检测镜头切换

做什么用 ffmpeg 的场景检测滤镜扫描整段视频，找出画面发生突变的时间点——即镜头切换的位置
输入原始视频文件 + 场景阈值（密度档决定灵敏度：密集档更敏感，稀疏档更粗放）
输出一组时间戳数组，标记每个镜头的起始时刻。例如 [0, 2.5, 5.1, 8.3, ...]
代价FREE 纯 ffmpeg 本地处理，一段 5 分钟视频约 2-3 秒

这是整条管线的起点。后续所有步骤——抽帧位置、镜头合并边界、节点时间区间——都建立在这组时间戳之上。阈值越低检出越多（快剪视频可能 100+ 个切换点），越高越少（慢节奏纪录片可能只有十几个）。

02抽取关键帧

做什么根据上一步的镜头切换点，从视频里抽出一批静态画面（JPEG），作为后续分析的视觉素材
输入镜头时间戳 + 目标帧数（由密度档和视频时长决定）
输出一组 JPEG 文件，每张标注了所属镜头的时间区间和在视频中的精确秒数
代价FREE ffmpeg seek + 解码，约 50ms 一帧

分配策略：每个镜头至少 1 帧（中点位置），长镜头按时长比例多分。抽完后做一轮 dHash 去重，画面几乎一样的帧会被合并。

设计要点
抽帧本身非常便宜（100 帧 ≈ 5 秒），所以不在这一步做裁剪。所有镜头都被覆盖到，裁剪的决定权交给下一步的预筛选。

03预筛选（本地初筛）

做什么用本地小模型（如 Qwen3.5-0.8B）逐帧看图，给每帧打上结构化标签：场景类型、主体、信息量评分、视觉签名
输入上一步抽出的全部候选帧（缩略图版本，320px 宽）
输出每帧附加一组标签（caption / salience / signature / isEmpty），然后按信息量精选出送给主分析的帧
代价LOCAL GPU 约 1.1 秒/帧，受固定时间预算约束（标准档 60 秒、密集档 120 秒）

预算约束机制

候选帧数可能远超预算（比如 100 个镜头但预算只够标注 54 帧）。此时不按顺序处理前 54 帧，而是均匀间隔采样镜头，优先保证不同镜头都被看到。预算内先覆盖镜头多样性，再给长镜头的额外帧。

精选逻辑

标注完成后做三轮筛选：删除空镜和极低信息帧 → 视觉签名去重（同一个场景不重复）→ 按 salience 评分取 top N。最终产出一组精选帧，数量由密度档决定。

可选阶段
这一步需要本地 GPU 和已下载的小模型。如果用户没有配置本地推理，管线会跳过此步，直接用上一步抽出的帧（只做 dHash 去重）。

04语音转写

做什么从视频里提取音轨，用 Whisper 模型识别出带时间戳的逐句字幕
输入视频的音频轨道（自动转为 WAV 格式）
输出字幕分段列表，每段包含起止时间和文字内容。例如 [{start: 2.1, end: 4.5, text: "大家好"}]
代价LOCAL 或 CLOUD，取决于配置。本地 Whisper 约为视频时长的 0.3 倍；云端更快但按量计费

字幕对分析质量影响很大——它告诉大模型「这个人在说什么」，而不只是「画面里有个人」。没有字幕的视频（如纯音乐 MV）会跳过这步，主分析只依赖视觉信息。

分界线
到此为止，所有素材已准备就绪：镜头边界、关键帧、帧标签、字幕。接下来进入 LLM 驱动的分析阶段，每一步都会产生 token 消耗。

05镜头合并

做什么把每个镜头的帧标签 + 字幕打包发给中等文本模型，让它为每个镜头写一段可读的描述
输入全部镜头的时间区间、所属帧的标签（caption / signature）、对应时间段的字幕
输出每个镜头得到一段 shotDescription（如「特写 · 女生尝试甜品并点头微笑」）和代表帧索引
代价CLOUD 中等文本模型，每 3 个镜头一批，并发处理。100 个镜头约 3-5 万 token

镜头合并是「金字塔管线」的核心环节。它把底层的碎片信息（帧标签 + 字幕片段）压缩成中层的语义描述，大幅减少后续主分析需要处理的信息量。没有这一步，主分析必须直接面对上百张原始帧，要么超出上下文窗口，要么丢信息。

06全局摘要

做什么综合所有镜头描述 + 字幕全文，推断视频类型并生成一段全局摘要
输入上一步产出的全部镜头描述、字幕全文、镜头统计信息（平均时长、切换频率等）
输出视频类型（如「美食 vlog」「产品评测」）、全局摘要（200-400 字）、叙事结构线索（开场 / 高潮 / 结尾）
代价CLOUD 中等文本模型，单次调用，约 0.5-1 万 token

这一步为主分析提供「上帝视角」。主分析在逐段处理时，能参考全局摘要理解每个片段在整体叙事中的位置，避免只见树木不见森林。

07主分析

做什么把关键帧图片 + 字幕 + 镜头描述 + 全局摘要一起发给视觉大模型，产出结构化的节点时间轴
输入精选关键帧（JPEG base64）、字幕分段、镜头描述、全局摘要、类型方法论规则集
输出节点数组——每个节点包含时间区间、标题、镜头描述、情感标签、剪辑手法、镜头运动等字段
代价CLOUD 视觉大模型，这是整条管线的主力消耗。图片 token 约 800 tok/帧，文本部分另计。5 分钟视频约 2-5 万 token

分段策略

视觉大模型有上下文窗口限制。管线会根据模型的 context size 自动决定是一次送完（单次模式）还是分段处理（分段模式）：

  • 单次模式：所有帧 + 字幕 + 方法论能装进一次请求 → 一次出完整结果
  • 分段模式：按镜头边界切成多段，每段独立分析产出节点，最后拼接

每段最多能装多少帧由模型上下文动态计算——128k 模型单段可装 ~70 帧，8k 本地模型降级到 12 帧兜底。

08方法论审计

做什么拿到完整的节点列表后，按剪辑方法论规则集逐条审计，并生成全局剪辑报告
输入上一步产出的全部节点、全局摘要、字幕、方法论规则集
输出每个节点的方法论标签（命中 / 违反哪条规则）、全局报告（节奏评价、结构分析、改进建议）
代价CLOUD 文本模型，单次调用，约 1-2 万 token

分段模式下，主分析的每段只看局部节点，无法做全局方法论打标。审计步骤拿到拼接后的完整节点列表，站在全局视角完成最后的审计和报告。

09成本速查

以一段 5 分钟、60 个镜头、标准密度档的视频为例：

阶段 执行方 耗时 Token 消耗
检测镜头切换 ffmpeg ~2s 0
抽取关键帧 ffmpeg ~3s 0
预筛选 本地 0.8B ~55s 0
语音转写 Whisper ~90s 0
镜头合并 中等文本 ~15s ~30k
全局摘要 中等文本 ~3s ~8k
主分析 视觉大模型 ~20s ~40k
方法论审计 文本模型 ~8s ~12k
合计 ~3 min ~90k tok
注意
预筛选和语音转写的耗时最长，但成本为零（本地运行）。真正花钱的是后四步的云端模型调用，其中主分析占了近一半的 token 消耗。

10三个关键概念

PYRAMID
金字塔管线
底层用便宜的工具（ffmpeg / 小模型）做粗加工，中层用中等模型做语义压缩（镜头合并 + 全局摘要），顶层只让贵的大模型看精选后的内容。每一层向上传递的是更浓缩的信息。
BUDGET
预算约束
预筛选有时间预算（30-120 秒），主分析有 token 预算（由模型 context size 决定）。预算不够时不是简单砍掉，而是智能降级：均匀采样镜头、分段处理、动态调整每段帧数。
CACHE
逐层缓存
每个 LLM 阶段都有独立的缓存层（基于输入内容的 SHA256 key）。重新分析同一视频时，未变化的阶段直接复用上次结果，只有参数变更的阶段才重新调用模型。

备注

  • 本文档描述的是 v2 金字塔管线架构，对应 PIPELINE_VERSION 常量。
  • 耗时数据基于 Apple Silicon M 系列本地 + GPT-4o 云端的典型场景，实际因模型和网络波动。
  • Token 消耗为估算值，视频内容复杂度和字幕密度会显著影响实际用量。
