# 字幕关键词高亮验证

更新时间：2026-07-24

## 结论

ClipIQ 现在会把可靠的词级字幕和事件语义合并为可追溯的 `CaptionCue.highlights`，并在 FFmpeg 代理预览的 ASS 烧录字幕中显示关键词强调。

高亮不是只存在于渲染字符串里的装饰。每一项都记录：

- 字幕内的字符起止位置。
- 对应文本。
- 时间线微秒起止时间。
- `event_keyword` 或 `number` 原因。
- 置信度。

这样后续导出器、人工编辑和质量评估可以读取同一份结构化结果。

## 选择规则

首版使用确定性、保守规则：

1. 必须存在有效词级时间；只有句级字幕时不高亮。
2. 数字词可以成为高亮。
3. 普通词必须和当前镜头的事件摘要存在至少两个连续字符的重合，且覆盖该词至少 40%。
4. 单条字幕最多选择两个高亮，按语义匹配和转写置信度排序。
5. 找不到词在字幕文本中的精确字符位置时跳过，不猜位置。

这套规则不会调用新的 LLM，也不会把所有长词都当成关键词。后续可以把 Planner 明确选择的关键词写入同一数据结构，而不改渲染契约。

## 时间与编辑一致性

- 素材词级时间按 `VideoClip.sourceInUs / timelineInUs / speed` 换算到时间线。
- 镜头移动、裁切或卡点变速后，从片段证据重新生成词级时间和高亮。
- 替换镜头后使用新镜头的字幕、事件和词级时间。
- 用户人工修改字幕文本后，立即清除旧 `wordTimings` 和 `highlights`，防止旧位置套到新文字。
- Validator 检查字符范围、文本一致性、时间范围、重叠和置信度。

## 渲染和降级

- 烧录模式生成 ASS，普通字幕为白色，关键词使用单一强调色。
- 外挂字幕仍生成纯文本 SRT，保持通用播放器兼容。
- 项目自带的 libass FFmpeg 已真实渲染 720×1280 H.264 样片，字幕和强调色均正常。
- FFmpeg 没有 `subtitles` filter 时，继续按既有策略降级为外挂 SRT。
- 代理 renderer version 已提升，旧缓存不会遮蔽新渲染结果。

## 验证

- 事件关键词、数字和置信度排序。
- 素材时间经过变速后的微秒换算。

- ASS 特殊标签和纯文本 SRT 分离。
