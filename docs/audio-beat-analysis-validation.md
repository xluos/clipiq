# BGM 节拍分析验证

## 当前链路

Studio 选择本地音频后，Electron main 执行以下确定性链路：

1. FFmpeg 将来源音频限制到当前粗剪时长，解码为 `16 kHz / mono / f32le`。
2. `energy-onset-v1` 计算局部能量起音、周期自相关、节拍相位和 BPM。
3. 分析结果以 `AudioBeatAnalysis` 写入 `EditPlan` 的 `music` 音轨。
4. 只为距离不超过 `150 ms`、且前一镜头变速不超过 `5%` 的硬切边界生成 `BeatSyncSuggestion`。
5. 用户逐个确认建议后，轻微调整前一镜头速度，让目标硬切精确落到节拍；字幕、原声和后续时间线统一重排。
6. 添加、替换、移除 BGM 和确认卡点都生成新的 `EditPlan revision` 与反馈事件；镜头调整后重新计算建议。
7. FFmpeg 代理预览复用已有 music 混音、淡入淡出和旁白 ducking。

低置信度、音频过短、没有稳定周期、只有叠化边界或需要明显变速时不生成卡点建议。卡点必须由用户确认，不会自动改动时间线。

## 固定信号验证

验证日期：2026-07-24

输入：

- FFmpeg `aevalsrc` 生成的 8 秒点击音。
- 间隔 `0.5s`，目标 `120 BPM`。
- 通过产品相同的 `analyzeAudioBeatSource` 入口解码和分析。

结果：

```json

  "bpm": 120.4,
  "confidence": 0.9172032225404292,
  "firstBeats": [27429, 525714, 1024000, 1522286, 2020571],
  "beatCount": 17

```

节拍间隔约 `498 ms`，与固定信号一致。首个节拍约有 `27 ms` 起音窗口偏移，在当前 `150 ms` 建议容差内。

## 自动化覆盖

- PCM 解码参数与 f32le 解析。
- `120 BPM` 固定点击音恢复。
- 静音与低证据降级。
- 卡点容差、叠化过滤和无副作用建议。
- BGM 添加/移除产生新版本。
- 镜头缩短后卡点建议自动刷新。
- 用户确认后切点精确落到目标节拍，原方案保持不变并生成可撤销版本。
- 过期建议、已对齐建议和超过安全变速范围的建议被拒绝。
- 越界、乱序、过期的节拍证据被 `EditPlan` 校验拒绝。
