# 剪映兼容性 Spike

更新时间：2026-07-24

## 结论

当前开发机没有安装剪映专业版或 CapCut，也没有现成草稿目录。2026-07-24 续测再次通过本机应用列表确认两者均不存在。因此本轮只能完成候选实现审计和草稿结构验证，不能宣称通过“剪映可打开、重启后仍可打开、手工导出”三项真机验收。

在拿到目标剪映版本前：

- 不进入正式剪映草稿导出器实现。
- M5 先按“可诊断的素材包”降级路线设计。
- 如果产品允许使用 CapCut 国际版，`capcut-cli` 可以继续作为候选。
- 如果必须使用新版剪映，优先用 `pyJianYingDraft` 生成独立新草稿做真机 Spike，不读取或覆盖用户已有草稿。

## 自动环境探测

已增加只读探测命令：

```bash
npm run vlog:probe-editing-app -- --json
```

探测内容：

- `/Applications` 和用户 `Applications` 下的剪映专业版 / CapCut。
- `Info.plist` 中的 bundle ID、版本号和 build。
- macOS 常见草稿根目录及用户目录中发现的同类路径是否存在、可读、可写，以及已有项目数。
- 当前精确版本是否进入真机验证矩阵。

命令不会启动应用、创建草稿目录或修改已有项目。renderer 也可以通过 `detectEditingAppEnvironment()` IPC 读取同一份报告。

2026-07-24 当前机器实测：

- `readiness = not_installed`
- `exporterReady = false`
- `installations = []`
- 四个已知剪映 / CapCut 草稿根目录均不存在
- 退出码为 `1`，用于阻止自动化把未安装环境当成通过

真机验证矩阵目前保持空。只有五个固定用例、重启重开和手工导出全部通过的精确版本，才能加入 `VERIFIED_EDITING_APP_TARGETS`；安装但未验证的版本最多进入 `ready_for_spike`，不能令正式 exporter 解锁。

## 真机报告门禁

已增加可复核的报告契约和只读校验命令：

```bash
cp docs/jianying-spike-report.example.json /path/to/spike/report.json
npm run vlog:validate-jianying-spike -- /path/to/spike/report.json
```

报告中的 fixture manifest 和证据路径都相对于 `report.json` 所在目录。校验命令会重新读取当前机器，而不是信任报告内的环境声明，并同时检查：

1. 当前应用的 kind、名称、bundle ID、version、build 和安装路径与报告完全一致。
2. 当前环境仍为 `ready_for_spike`，草稿根目录仍可读写。
3. 隔离草稿目录真实存在，且是草稿根目录的严格子目录。
4. fixture manifest 和每项证据文件真实存在、不是符号链接，SHA-256 与报告一致。
5. 以下九项检查全部为 `passed` 且各自至少有一份有效证据：
   - 视频裁切、排序和时间线
   - 原声、BGM 和旁白音轨
   - 中文字幕
   - 转场和自定义图片贴图
   - 保存、退出、重启和重开
   - 手工导出
   - 中文和空格路径
   - 源素材移动或缺失诊断
   - 用户已有草稿未被覆盖

命令返回 `0` 才表示报告有效；未通过返回 `1`，参数或 JSON 无法读取返回 `2`。`passedCheckCount` 只统计证据文件和哈希也验证成功的项目，不能靠手改 `status = passed` 增加。

有效报告会产生带 `bundleId / version / build / reportId / testedAt` 的 `target`。支持矩阵也要求这些字段完整匹配，只有版本号不能解锁 exporter。示例报告故意保持全部 `not_run` 和占位字段，用于填写模板，不是通过凭证。

## 固定测试素材

测试素材全部在临时目录生成，不写入 ClipIQ 数据目录：

- 两段各 2 秒、带原声的 720×1280 H.264/AAC 视频。
- 4 秒 BGM。
- 4 秒旁白音频。
- 两条中文字幕 SRT。
- 一张 PNG 自定义贴图。
- 所有草稿、素材和文件名均包含中文与空格。

## 候选实现审计

### `capcut-cli`

审计版本：

- npm 包版本：`0.14.0`
- Git commit：`233357fb69da2213ea879f6be912c728e5189001`
- 仓库：<https://github.com/renezander030/capcut-cli>

结构验证结果：

- 可创建两段视频并排序。
- 可添加 BGM 和旁白音轨。
- 可导入两条中文字幕。
- 可添加叠化和 PNG 叠加轨。
- 中文、空格路径可用。
- `lint` 为 0 error / 0 warning。
- 自带 FFmpeg 代理渲染可生成 4 秒 H.264/AAC 文件。
- 当前机器 FFmpeg 不含 `drawtext`，代理渲染中的字幕烧录被明确跳过。

不满足点：

- `init` 使用的内置模板固定为 `platform.app_source = "cc"`、`app_version = "6.5.0"`，本轮生成的是 CapCut 草稿，不是剪映原生草稿。
- `--jianying` 只切换转场、特效等枚举命名空间，不会把新建草稿变成剪映草稿。
- 项目自身兼容矩阵把剪映 `6.0+` 加密草稿标为不可直接修改；只能检测，不能解密。
- `init --help` 会把 `--help` 当项目名并产生写入，不适合作为未经封装的 Electron 子进程接口。本轮意外生成的默认 CapCut 测试目录已立即移出原路径并保存在临时恢复目录。

判断：适合继续评估 CapCut 国际版路线，不足以证明新版剪映兼容。

### `pyJianYingDraft`

审计版本：

- Python 包版本：`0.3.0`
- Git commit：`c3318066d964744e2bfc66f75c71745fe8cea52a`
- 仓库：<https://github.com/GuanYixuan/pyJianYingDraft>

结构验证结果：

- 成功生成独立 `draft_content.json`。
- 主视频轨包含两段裁切素材。
- BGM、旁白各自位于独立音轨。
- 中文字幕生成两个 `type = "subtitle"` 文本素材。
- 叠化转场包含 300ms 时长和剪映资源 ID。
- PNG 自定义贴图位于独立视频叠加轨。
- 素材路径包含中文和空格时均可解析，所有引用文件存在。

未验证点：

- 没有目标剪映应用，无法验证草稿能否被 macOS 剪映发现和打开。
- 无法验证重启后重开、保存和手工导出。
- 项目文档说明 macOS 支持草稿生成和模板模式，但不支持自动导出；新版模板读取还可能需要额外 `fallback_loader`。

判断：更接近“生成剪映新草稿”的需求，但必须经过目标版本真机验证后才能进入 M5。

### 自建 exporter

本轮不实现。缺少目标版本创建的最小真实草稿样本时，自建 schema 只会重复第三方项目的逆向工作，无法提高可打开率。

## 真机续测清单

1. 安装并记录首个目标剪映版本，关闭自动升级。
2. 运行 `npm run vlog:probe-editing-app -- --json`，保存版本和路径报告。
3. 在剪映中手工创建一个空白草稿，确认真实草稿根目录。
4. 复制空白草稿到隔离测试目录，保留原件不写。
5. 用 `pyJianYingDraft` 生成本页固定用例草稿。
6. 重启剪映，打开草稿并核对媒体、字幕、音轨、转场和贴图。
7. 保存、退出、重启并再次打开。
8. 手工导出，记录缺失资源、时间偏移和兼容性错误。
9. 为每项检查保存截图、导出文件或诊断日志，计算 SHA-256 后填写真机报告。
10. 运行 `vlog:validate-jianying-spike`；只有返回 `0` 并产生 `target`，才把该目标写入支持矩阵并启动 M5 草稿导出器。
