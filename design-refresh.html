Design Rationale

三个改造的取舍说明

01Home · 砍掉“本地 vs 链接”的二选一

原界面要求用户先在“本地视频”和“链接拉取”两个大卡片里选一个。这是一个无意义的决策:同样的项目,同样的分析管线,只是输入源不同 —— 强行让用户分类是把内部架构暴露给了用户。

新方案是一个智能输入框,自动识别粘贴的链接、拖入的文件、输入的本地路径。下方 hint 条实时反馈识别结果,用户不需要选模式。url_pull 这一整个 screen 不再需要 —— 链接拉取的进度日志合并到“进行中”项目的进度条里。

改前
7 个 screen, home/url_pull 是两个独立入口, 状态切换由 ScreenState 切片驱动
改后
6 个 screen, home 是唯一入口, url_pull 退化成 home 进行中卡片上的进度条 + 错误回退
代价
需要在 home 内联失败重试 / 切换为本地的逻辑; UrlPullScreen.tsx 可整文件删除

02Workspace · 节点信息分级

原节点卡片塞了 6 类 badge + 代表帧 + 镜头描述 + 字幕分段 + 方法论命中违反,展开后能占半屏。用户拉片时大部分时间只需要“这是第几个节点、什么时间、什么主题”,详情是请求型信息,不是默认信息。

新方案默认每个节点只显示 timestamp + title + 至多 1 个 primary badge(钩子 / 关键 / 结尾 / 高光),meta 行用 mono 排印,信息密度极低。点击 chev 才展开看 shot description、代表帧、方法论 audit。同时“逻辑节点 / 严格镜头”从 3 tab 收敛成 2 segmented control,“概览”变成右侧顶部一张可独立展开的 summary card,不参与切屏。

改前
Tabs grid-cols-3 切屏, 节点卡片信息密度无分级
改后
summary 始终可见, segment 在节点 / 镜头之间切, 节点默认折叠
代价
需要在 NodeCard 上加 open state + 折叠动画; representativeFrames 渲染条件改

03Settings · 管线图代替槽位矩阵

原 6 槽位矩阵(simple_vision / medium_text / ...)是从工程视角设计的:开发者知道哪一档对应哪个调用点,但用户不知道。当用户看到“simple_vision”时,得反推“这是哪个调用点”。

新方案用具象的管线流程:01 抽帧初筛 → 02 字幕识别 → 03 镜头合并 → 04 主分析。每一步旁边一个 picker 直接挂 provider + model。槽位的能力标签(vision / text / fast)以 badge 形式辅助说明,而不是作为分类轴。供应商列表退到下方,只负责“给上面的管线提供选项”,本地推理和远端 OpenAI-兼容用同一抽象。

改前
6 槽位矩阵 + 供应商列表 + 本地推理 + Whisper 四个独立 section, 用户得自己拼起来
改后
两段式: 管线图(主) + 供应商池(辅), 本地与远端同卡片格式
代价
需要把 simple_vision/medium_text 这种 key 在 UI 层映射成“抽帧初筛 / 镜头合并”这种业务名; 数据层不动

04视觉语言收敛

原视觉用了 slate + indigo + 若干 shadow 层级,在某些 screen 上出现紫粉味的渐变倾向。新方案的方向是 Editorial / quiet:

  • 分层主要靠 1px border + 极浅的 muted 背景,几乎不用 shadow
  • indigo 只用在 primary CTA、当前节点高亮、is-active state,其他地方一律 slate
  • 所有时间戳 / 模型名 / 端口 / 文件名走 monospace,与正文形成节奏
  • 圆角收敛到 6 / 8 / 12 三档,徽章是 4px,小按钮 6px,主容器 12px,不再 rounded-xl/2xl 混用

05没改的部分

PrepareScreen / ProgressScreen / ReportScreen 这次不重设计。三个 screen 现在的问题各自存在,但优先级低于 Home / Workspace / Settings:

  • Prepare: 配置项过多,但属于每个项目只用一次的页面,改造收益低
  • Progress: 在新 Home 方案里会被合并成项目卡片的进度条 + 一个 modal 看阶段详情,不再是独立 screen
  • Report: 信息架构复杂但合理,目前 scroll-spy 导航靠谱,8 个 section 自洽。重点应该是“在 workspace 内联看 audit”,而不是改 report 本身
